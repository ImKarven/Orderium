# Contributing to Orderium

This is a guide for people who want to help improve this project.

### Creating a Pull Request
You can create a pull request for a simple feature or a bug fix.
<br>
You may open a PR to resolve an issue in the Issues Tracker if no one is assigned to it.
<br>
You should not open a PR for a feature that require large changes, open an issue and describe it instead.

### Pull Request Guidelines

1. **Compatibility**
  - Any changes must be compatible with Paper **and Folia**.

2. **Pull request formatting**
  - Create a new branch for your feature or fix when forking the repository.
  - Reference related issues in your pull request description if applicable.
  - Write clear and descriptive commit messages.

3. **Code styling**
  - Add code comments for complex logic or significant changes.
  - Try to keep your code clean and avoid duplication.
  - Thoroughly test your changes before submitting your pull request.

### Reviewing PRs
In case you well understand how Orderium works and have experience with programming, you can review open PRs.
